# 研究笔记：avatar 分支方向分析与主干落地清单

> 分析对象：`origin/avatar`（数字分身方向，merge-base f81e210 = v0.12.0；
> 领先 main 15 提交，落后 9）。结论日期：2026-10-16。
> 本文是研究笔记与落地建议，非合并决定——分支维持探索态，不合流。

## 1. 结论摘要

1. **avatar 不是与 theater 竞争的第二套 UI，而是它的下一层**。theater 回答
   "舞台（此刻）长什么样"，avatar 回答"房子（容器）长什么样"——两者在
   "舞台自持整窗"上已经相同（theater §17.6 与 avatar §6.1 各自独立得出），
   真正对撞的只有容器三文件（identity-shell / home / command-palette）。
2. 方向的品味核心是**隐喻机制账**（avatar.md §3.2："每多一个生命隐喻必须
   挣到一个已存在机制"）+ **后端零改动**硬边界 + **窗口诚实**标注纪律。
   这三条本身就该成为主干纪律，与合并与否无关。
3. 主干有 6 件马上可落的事（§5），全部**只增不改**（新文件或双方未触碰
   的文件），不给将来的合流制造新冲突面。
4. 合流建议（§6）：让 avatar 分支尽快 rebase main（9 个提交里有 Job Object
   安全修复）；主干在容器三文件上**冻结结构性改动**（行为修复照常）；
   三文件冲突留一次设计裁决一次解完。search-jump 已给出好先例：同一 bug
   两侧独立修复，产出**逐字节相同**——收敛方向一致时，合并比看起来小。

## 2. avatar 方向是什么

组织轴替换：界面从"软件域"（路由/设置/配置表单：usage=计费面板、
sensors=设备管理器、schedule=crontab）换成**生命域**（食量/睡眠/作息/
感知/手艺/社交/体检/手账/日记）。全部界面只回答三个问题：

| 问题 | 篇 | 定稿图 |
|---|---|---|
| 它以什么存在 | 形态 | 生命体解剖（六根+生命系统环） |
| 它往哪里长 | 进化 | 同行曲线（起步期→同行期→分身期，推进只靠用户放权） |
| 它经历过什么 | 传记 | 时间望远镜（缩放即时间旅行，五档收编全部时间视图） |

对主干现状的诊断依然成立（D1-D4）：8 个平铺 tab 的容器是管理后台；
六个时间视图靠 tab 缝合；**没有一个面回答"它长大了多少、离替我出面
还差什么"**——而成长正是产品目的（用户 2026-10-14 拍板的关系定位：
老师+伙伴+主人 → 数字分身）。

工程上它是纯投影层重组：53 文件 ±6k 行，后端零改动；lib 层
（growth-ledger / growth-dossier / diary / attention / vitals）全部纯函数
+ 双测试，数据全部来自既有端点。

## 3. 与 theater 的分层关系（合并比看起来小）

- **一致的**：舞台自持整窗；⌘K 为一级入口（主干已有 command-palette，
  avatar A 期在其上升格——同方向）；对话单真相源；年轮视觉底座；
  数据诚实/禁庆祝/reduced-motion 全部红线。
- **互补的**：theater 的舞台四层+五态宇宙 = avatar 形态篇的"身"；
  avatar 的体征带/食量/体检 = theater 心跳行的展开。
- **真对撞的只有三处**：
  1. `identity-shell.tsx`：主干"剧场顶栏 + NAV chips" vs avatar"零 tab 居所
     （⌘K + X 光）"——设计裁决题，不是文本冲突题；
  2. `home.tsx`：主干工作台 vs avatar 重生为"同行面"（共同成长账三栏）；
  3. `command-palette.tsx`：两侧各自扩展（主干加身份分区，avatar 加动作组）。
- 低频管理页的去向（X 光线框叠加 vs 保留运行四页/设置）是 §6.1 的最大
  未决语义：X 光态下 confront 卡、审批、表单类配置（providers/凭据）的
  归宿需要专门梳理——"必须表单化的收进工作台抽屉"目前只是一句话。

## 4. 方向的风险与纪律

1. **隐喻疲劳是真实风险**：九个生命系统面的隐喻密度很高，机制账是唯一
   防线——任何一处数据源弱于隐喻（如 S0 沉淀未落地先画"做梦"）就塌成
   装饰。avatar 自己已有此自觉（差异逐条留痕 §10.1），主干吸收时要把
   "机制账"当作验收项而非风格偏好。
2. **窗口诚实**：轨迹查询是行数窗口不是时间窗口——凡按"今日"表述的
   计数必须带 `windowCoversToday` 式下界标注（"近 N 步内"），否则是
   假指标。growth-ledger.ts 的实现是范本。
3. **反游戏化**：无经验条无等级；"放权可逆、不自动放宽、成长不可自我
   加冕"三条伦理（§4.4）与主干 FINAL 机械验收同一哲学（模型单方面
   宣告不被采信）。
4. **双设备并行的合流成本在上升**：分支每拖一天，落后 main 的提交越多
   （已含 Job Object 安全修复）。search-jump 的逐字节收敛是运气+方向
   一致；identity-shell 的对撞不会每次都这么便宜。

## 5. 主干马上可落清单（全部只增不改，不新增合流冲突面）

> 原则：avatar 已整体重写的路由/组件（sensors/usage/home/identity-shell/
> command-palette/scene-layer 等）主干**不再动**；主干落的东西必须是
> 新文件，或落在双方都没碰的文件（talk-strip / scene-cosmos / app.css /
> lib/scene.ts 等）。已经必然手工合并的文件（三冲突文件）里加一小块
> hunk 的边际成本可接受，但也仅限接线。

| # | 事项 | 动什么 | 值什么 | 成本 |
|---|---|---|---|---|
| P0-1 | 本文入库 | docs/research/（新文件） | 思路存档 + 给对面设备的合流信号 | 零 |
| P0-2 | **窗口诚实审计**：主干现有读数面（引擎室抽屉"最近轨迹 5 条"、ThreadsRow、记忆计数）凡行数窗口按时间表述的，补下界标注 | 各自组件内一行文案 + 布尔判断；不碰 avatar 文件的可直接改，碰的记入合流清单 | 数据诚实红线在主干现有面上补齐 | 小 |
| P0-3 | **sensors 学习期判据口径核对**：avatar 修了"LearingDays omitempty 漏报缺省学习期感官"——主干 sensors 页同口径核对，坏则修 | sensors.tsx 主干版（avatar 重写前先小修，合流时以 avatar 版为准） | 读数不说谎 | 小 |
| P1-1 | **体征带进舞台**（vitals-band + lib/vitals 整体移植，含 awaiting 桥=三化身同源第一步）：呼吸/心跳/食量/痛觉常驻读数 | 新 lib + 新组件（自包含）；scene-layer 挂载点一个 hunk（该文件已在合流清单，边际成本≈0） | 北极星"眼睛里有事"：瞥一眼知道活着没/饿不饿/疼不疼；与桌宠同一份五态信号系 | 小-中 |
| P1-2 | **成长档案一章**（growth-dossier.ts + routes/growth.tsx 整体移植，自带 6 测）：同行曲线三段带 + 自主权边界只读读数 + 传承清单（仅偏好类证据链，永不显示百分比） | 新 lib + 新路由 + identity-shell 一个 NAV 项（已在合流清单）+ routes.ts 一行 | 补 D4 目的缺席：主干第一个回答"它长大了多少"的面 | 中 |
| P1-3 | **共同成长账卡进工作台**（growth-ledger.ts + 测试整体移植）：它为你/你为它/一起长出，三栏今日账，窗口诚实标注 | 新 lib（自包含）；home.tsx 一张卡（avatar 反正要重生 home，边际成本≈0） | 双向记账原则落主干；审批/taste/记忆数据本来就是主干机制 | 中 |
| P2-1 | **机制账词表成为主干新代码纪律**：此后主干任何新文案用生命域词表（食量/手账/同行账/放权/转正），且每个隐喻必须指认机制事实源 | 无代码；写进 theater.md 附注或 ui-language.md | 主干与 avatar 语言收敛，合并时语义冲突持续变小 | 零 |
| P2-2 | **⌘K 渐进升格**：主干 command-palette 补"动作组+新建委托"分区（向 avatar A 期靠拢），低频入口逐步收进面板 | command-palette.tsx（已在合流清单，且两侧同方向演进=冲突可解性最好的一处） | 为零 tab 容器铺路；每次都让未来合并更小 | 小 |

**明确不现在做的**：零 tab 容器切换、home 重生为同行面、X 光替代管理页、
时间望远镜缩放轴、三化身参数同源化——这些是合流时一次裁决一次做完的
容器级事项，主干现在动手只会加大（而不是减小）最终合并成本。

## 6. 合流策略建议（给两边）

1. **节奏**：avatar 分支尽快 rebase main（9 个提交里 Job Object 连锁杀
   修复是安全件）；此后每落地一期 rebase 一次，落后不超过 10 个提交。
2. **主干冻结面**：identity-shell / home / command-palette 三文件的
   **结构性**改动冻结至合流（行为性修复如对话条照常——talk-strip
   avatar 完全没碰，已验证零冲突）。
3. **三冲突文件一次裁决**：需要用户拍板的只有两问——①低频管理页去
   X 光还是保留（表单类归宿）；②home 第一屏是工作台还是同行面。
   其余（⌘K 扩展、NAV 收编）两侧已同向，按"avatar 版为基、主干增量
   回植"解。
4. **验收**：合流后跑 avatar 自带 smoke（uitest/avatar-smoke.mjs）+
   主干全场景（S12-S18）+ 台账累积。
