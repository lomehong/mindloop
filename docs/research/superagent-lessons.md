## 0. 顶层框架：核心思想领会（v2 补记）

> 本节由负责人质询触发补记。初版总纂按文章五模块逐节对照（跟随文章
> 结构）；本节改按文章的问题定义层重组（跟随文章的倒推逻辑）——
> 「覆盖全部章节」与「领会核心思想」是两个标准，初版只满足了前者。

### 0.1 四特征打分（文章的问题定义 → mindloop 的覆盖度）

文章全部架构都是从四个特征倒推的；用同一把尺子量 mindloop：

| 特征 | 文章定义 | mindloop 现状 | 判定 |
|---|---|---|---|
| 连续 | 跨信道如同一个 Agent | 身份即入口，底层身份→多轨迹已解耦（用户界面上一个会话≠底层一个 Session，恰是 8.2 预言的形态）；信道实装企微+web 面板+pet（钉/飞 2026-10-05 裁决不做，架构上 connector 家族信道无关） | ✅ 架构在，宽度受限 |
| 高效 | 并行多任务无需等待 | 对话半边 ✅：responder 独立槽，任务跑着对话照常（§4）；任务半边 ❌：单 Worker 串行，三重封顶，N 任务排队上界 30min×(N-1)（推断，常量推导） | ⚠️ **唯一结构性缺口** |
| 主动 | 观察事件无人 @ 也推进 | 感知系统五感 + S0-S3 四级 + 四闸 + 学习期（§3）——比文章两级过滤更细 | ✅✅ 超配 |
| 持久 | 在线 + 异常自愈 | OS 宿主活性 + 调度器合成唤醒 + 监督快照 + Nuwa 外部修复，四层（§4） | ✅ |

文章实验里 Super-agent 的全部优势（p95 29.5→15.7 分钟）来自并行
Worker——恰好落在 mindloop 唯一的结构性缺口上。这不是巧合：四特征
里其余三个 mindloop 都已独立收敛，剩下的就是这条。

### 0.2 核心主轴一：「接管—上移」循环，文章管注意力、mindloop 管信任

文章的暗线是：**系统每接管一项繁琐层，人就被释放上移一层**——接管
会话管理（双层架构）、上下文同步（Inline&Spill/链式召回）、并发调度
（Router/Worker）、自愈（Watchdog），人从打字员上移到「决策与验收」。

mindloop 走的是同一条循环的**正交轴**：接管执行信任（policy 分级/
tripwire）、可撤销性（undo）、凭据隔离（不进上下文）、完成判定（FINAL
机械验收），人从逐脚本审批上移到 auto 档放行 + 验收。

两条轴合起来才是一个完整的自主协作者：**注意力基础设施 × 信任基础
设施**。这统一了本文档的「领先项」与「缺口」——§8 的 13 项领先几乎
全是信任基础设施（文章空白），「高效」缺口恰是文章的主场。对 mindloop
的启示不是「落后了」，而是：**文章五模块解决的是「该让它同时干几个」，
mindloop 信任体系解决的是「该不该让它干」——前者文章给了图纸，后者
mindloop 信任轴领先但未闭合（§7.0 的自我改写面正是未闭合的证据）。**

### 0.3 核心主轴二：「相似约束→相似架构」的预言价值

文章原话：「相似的设计约束会导出相似的架构选择……底层就可能采用
相近的架构」。这句话对 mindloop 的真正价值不是对照表，是**预言**：

- **已收敛站点**（commit `9ad927b` 自评 + 本对照确认）：coalesced≈
  Batching、判级≈两级过滤、注入预算≈Inline&Spill、recap 分层≈Spill
  粗细层、监督快照≈Watchdog 半场、robotd≈端侧无状态效应器。
- **前方必经站点**（做这类系统大概率逃不掉）：Thread 事件流建模、
  任务归属直通、链式召回注入约定、方向研判第二双眼；若并发负载到来，
  Router/Worker 分层（fork 原语已备）。

行动含义：§5 的可借鉴清单应读作「必经站点清单」——问题不是「要不要
抄」，而是「何时到站」，到站时间由负载证据（P0-4 饥饿统计先行、
消融实验后补）决定，不由架构热情决定。

### 0.4 Token 经济学：不是脚注，是 D1 的决策框架

并发化的 token 代价：以文章数据自算为 **2.1–3.8 倍**（2323 万 vs
优先委派基线 1082 万 / 中性基线 605 万；论文未给倍数，取最差基线
得「约 4 倍」是本文档 v1 的包装错误，v3 更正）——本质是「算力换人的
注意力」。对照组的不对称要如实看两面：单 Session 的 29.5 分钟里含
「被新消息打断重做」的浪费，mindloop 分槽隔离没有这个问题；**但
mindloop 串行的损失也不止排队延迟**——任务在途期间事件唤醒被任务
attempt 消费（Claim 是唤醒第一动作，monolith.go:215-217）、S2/S3
研判饥饿最长 30 分钟×N、last-wins 合并吞掉同源中间事件（§2）。对
个人部署（每日预算守卫 + 自发档限额）+ 单用户日均任务量，「倍数级
token 买并发」大概率不划算——这是 D1 维持「不是则不动」的经济学
依据；决策证据用 P0-4 饥饿统计（零代码）先取，不等消融实验。

### 0.5 v2 补遗三项（初版遗漏）

1. **Co-design（文章 8.1，初版完全遗漏）**：论文原列三项——针对
   Router 层的**事件判别、批量分派、上下文召回**做模型专项训练
   （v1 把「方向研判」混入清单是转述越界，v3 更正）。mindloop 落点：
   若演进 Router 型职责（判级/召回），选型时考虑针对性提示/微调——
   与双模型分层（思考/请求档）同族思路的深化。
2. **「聊天窗口是路径依赖」（文章 8.2 深意，初版只给了中途介入）**：

   宠物播报/任务看板/仪表盘领域页签都是领域界面，chat 只是入口之一）

3. **A2A 与组织边界（文章 8.3）**：初版散在 interaction 轴 Q5 未入
   顶层——mindloop 身份=上下文隔离单位、「显式发布不做隐式共享」与

   已有寻址半落地（§4）。

## 2. 调度与并发轴

**结构等价**（事实）：dispatcher 是 Router 的程序化骨架（订阅路由
dispatcher.go:469-537、cursor 从 EOF 起步 dispatcher.go:215、背压二分
dispatcher.go:110-138）；responder 是 Router 的人类交互面（只订 message、
单次调用，responder.go:36-38,123-127）；monolith 是单 Worker。判断
（推断）：responder+dispatcher 构成「恰好一半 Router」——交互连续性 +
程序骨架在，缺 LLM 协调大脑；文章 2.1 自己说 Router「部分逻辑未必需要
调用 LLM」，mindloop 把「未必」推到「全部」，代价是失去跨任务语义分派。

**文章 7.1 的失败模式 mindloop 已结构性规避**（事实）：委派是入口纪律
不是模型临场判断——「普通聊天不是新的执行授权」+ 唤醒第一动作 Claim
（monolith.go:33-35,215-217）+ responder/monolith 分槽物理隔离。文章
中性提示下模型 5 次运行 0 次委派（文章 §7.1），mindloop 无此依赖。但 12.4/
15.7 分钟优势来自并行 Worker，mindloop 吞吐上限 = 1 任务/attempt，三重
封顶 16 轮（monolith.go:183-185）/24 次调用（tasks.go:61）/30 分钟
（dispatcher.go:657-658）。瓶颈画像（推断，常量推导非实测）：≥2 个长
任务并发提交时第 N 个排队上界 30 分钟 ×(N-1)；在途期间 S2/S3 研判时机
推迟到 attempt 结束（事件唤醒被任务 attempt 消费，且 coalesced
last-wins 会吞同源中间事件）。附带代价提醒：并发化 token 代价以文章
数据自算为 2.1–3.8 倍视基线而定（2323 万 vs 1082 万/605 万，文章 §7.1；
论文未给倍数），对有每日预算守卫的个人部署是真实取舍。

**fork/merge 演进可行性**（工程判断）：原语完备——CreateFork 双向引用
（traj/store.go:105-131）、Merge 回写（traj/append.go:102-121）、
**monolith 已订阅 merge 类型**（monolith.go:208，即「Worker 向 Router 汇报」现成钩子）；
「单目录锁+单 EOF」按轨迹独立成立，同机 fork 不触碰 roadmap §4 反对项
的正确性论证。三个待补缺口：并发槽（busy 单标志 monolith.go:163-176、
taskStore 单例）、上下文绑定（看板/记忆/recap 全从根轨迹派生
monolith.go:529-639，子轨迹无 recap 缓存）、事件可见性（调度器只 tail
根轨迹 dispatcher.go:215）。

**批处理对照**：文章是无损合批（推理期间积压一次注入，prefill 并行，
单决定分摊 6.4s→1.6s，文章 §7.2）；mindloop 是两层合批——叫醒层有损
（coalesced last-wins，合并键 type+source，dispatcher.go:129-138）、
内容层无损（事件全落轨迹、唤醒尾窗一次渲染）。差异（推断）：mindloop
合批窗口 = 整个唤醒期（最长 30 分钟）而非单次推理，积压更深但紧急事件
决策延迟更长。

## 3. 事件驱动与上下文轴

**两级过滤高度同构**（事实）：Fast = 判定层反射规则 + 准入令牌桶 +
dedup 指纹（sensorrun.go:329-347）；Slow = s2+ 唤醒后 monolith 按提示词
策略判断（monolith.go:28-49）。差异：文章是独立 LLM 过滤调用，mindloop
把语义判断合并进被唤醒思考者省一次调用（perception.md:256 明示第一版
不做独立判别）。mindloop 独有：S0-S3 四级、被滤事件治理闭环（学习期
封顶 perception.md:407-410、quiet 降级补看、gate-denied 降级为次日素材
不蒸发 monolith.go:314-316,341-361、S0 沉淀折叠 prompt.go:60-98）——
文章的过滤只答「进不进」，未答「被滤掉的去了哪」。

**链式召回：原子件齐、约定缺**（事实）：「一个 id 命名空间」+ merge 带
from_traj/from_step（append.go:114-119）+ Spill 续读逐字对应（
「完整内容: mindloop traj show %s --full」render.go:32；省略区
prompt.go:285）。缺三件：event 无 thread/parent 引用字段（subject 是
扁平字符串）；digest 只内联摘要不内联关联对象 ID；traj show --full 无
「同事务相邻事件」逐跳入口。与 BM25 正交互补：BM25 语义相似检索
（mem/index.go），链式召回结构引用检索。

**长程记忆**：recap 确定性切窗 + 摘要缓存永不重算（recap.go:110-144）
+ 人生分集粗层（recap.go:380-429）覆盖**时间压缩**维；未覆盖**跨月检索**
维——分集只注入最近 20 幕（recap.go:420-421）、分集渲染不带窗口步骤
ID 无回跳入口。文章 8.1 自认同样未解，此处是共同前沿而非差距。

**投机执行泛化**（推断）：核实型已落地；watchdog 空唤醒是天然投机预算
载体（自发档账目已隔离 monolith.go:242-244、空转率指标已有
roadmap.md:115-117），准备型场景（日程预热 PrefetchSeg
monolith.go:542-550 已有雏形）边际成本低。

## 4. 交互、存算分离与 Watchdog 轴

**心智级全双工已解决 4.1 的主要价值**（事实）：monolith/responder 分工
（monolith.go:208 不订 message vs responder.go:126 只订 message）+ 任务
运行上下文隔离（runner.go:302-311 剔除 message）+ SSE 活动卡
（README:301-310）。运行内异步化适用性低（推断）：中途注入破坏隔离
红线，失速守卫（同命令两次即死 runner.go:709-714）与 FINAL 副作用协议
建立在同步语义上。值得吸收的只有：模型自主 stop() 的 bash 层
「后台 nohup+下轮探针」惯用法（教学式，不动 runner 骨架）。

**多信道覆盖**（事实）：L1-L4 词限表（proactive-reporting.md:182-187，
L1 ≤100 字 / L4 ≤150 字）≈ 文章「IM ≤100 词」；S2 不上手机、手机只走
L3/L4（perception.md:411-413）；quiet 顺延 + 宠物勿扰双保险。缺口：
responder 对话面只有软教学「briefly and directly」（responder.go:24），
无硬规；长文分段是 18KB 字节切割（wecom.go:57）非内容密度定制。

**robotd 是文章 8.4 风险的爆炸半径缓解而非根除**（事实+推断）：独立
stdio server、不保存**心智/轨迹状态**（仅持会话级授权状态——窗口
白名单等，cmd/robotd/main.go:1-4）、缺省观察模式
（serve.go:27-28）、窗口白名单+会话级授权（server.go:13-15）、密码框
先行拒绝（server.go:8-9）、操作员空闲守卫（server.go:42-45）、act→feel
强制验证「禁止麻醉式自动化」（server.go:10-12）。文章场景「云脑失陷→
端侧全被控」在 mindloop 恰好有端侧独立授权层示范；但沙箱本身是全权限
（README:257-258），robotd 收窄的是桌面动作增量面。「心智在主机、身在

与跨网传输鉴权——远期裁决项。

**Watchdog 四层拆解**（事实）：①OS 宿主活性（Task Scheduler
RestartOnFailure，service.md:22,78）；②循环活性（合成唤醒
dispatcher.go:8-9）；③任务健康研判（监督快照，心智内部）；④崩溃级
修复（Nuwa：panic→qingniao 上报→修复 PR→failing_check 门，
nuwa.repo.json:3）。与文章第 6 节的差异（推断）：Nuwa 作用域是仓库
代码不监控运行中任务；监督快照在心智内部——主系统全死时随之死；
「方向是否偏离」（区别于「是否打转」）无第二双眼睛，已登记解法是远期
critic 第三思考者（roadmap.md:188-191）未实施——但它需要第三种上下文
（读任务书而不执行），与监督快照（同一 monolith 上下文内注入段）合并
两头不成立，形态裁决见 §6 D12。

**A2A 同向且半落地**（事实+推断）：身份=隔离上下文单位，to=<peer> 寻址
已就绪、显式发布记忆不做隐式共享（roadmap.md:185-187）——正是文章 8.3
「互不共享底层上下文、各代表权限边界」前提下的最小 A2A。未核实：对端
