## 1. 诊断：偏传统是隐喻层的结构性问题

年轮 v0.3 治好了视觉性格（D1/D5），但没动隐喻。把现状的每一屏
摆出来看，它们共同声称的隐喻是：

> **「运维控制台」——人是操作员，心智是被管理的对象，
> 界面的职责是把内部状态陈列给你看。**

证据（全部是当前实现）：

| # | 症状 | 结构性根源 |
|---|---|---|
| T1 | **七 tab 管理后台**：轨迹/对话/任务/记忆/运行/感官/设置——全部是"查看内部"的检修面 | IA 以"内部子系统"划分，不以"你与心智的生活"划分 |
| T2 | **Scene 是补丁**：宇宙层是背景视频，卡片是右上浮层——舞台没有成为界面本体，agent 的表达被钉在辅助层 | Scene 协议只做了"能发卡"，没回答"卡发到哪里、跟什么共存" |
| T3 | **对话是 tab 之一**：聊天要去对话页，卡片在另一层，宇宙在第三层——同一个生命的三种表达被三个路由切开 | 对话/卡片/宇宙没有共同的舞台 |
| T4 | **心智不在场**：打开应用看到的是数据表（步骤数/调用次数/预算），看不到"它"——持续运行的那个存在感靠文字状态行 | 缺一个以心智为主角的常驻呈现 |
| T5 | **动效是铬件级**：120/200/320ms 的态变有了，但没有叙事动效——agent 推一张卡、完成一个任务，界面没有"事件发生了"的戏剧表达 | 动效纪律（年轮 §3.4）只覆盖 UI 铬件，没覆盖场景叙事 |

**一句话**：我们把一个持续存在的生命，装进了一个它只能在里面
贴告示的行政管理软件。年轮给了它好看的制服，没给它舞台。

## 2. 方向：「剧场」——观测台之上，加一个共生舞台

### 2.1 双隐喻调和（不是替换）

年轮 v0.3 的「观测台」不废弃——**检修需要它**。新增的是它的另一面：

> **「剧场」——心智是常驻的演员兼导演；舞台是它表达与工作的
> 地方；人是观众、对话者与审批人。**

| | 观测台（已有，年轮 v0.3） | 剧场（新增，本文） |
|---|---|---|
| 隐喻 | 仪表台 · 标本 · 手记 | 舞台 · 光 ·在场 |
| 人角色 | 检修员（看内部） | 观众/对话者（看表达、给意图） |
| 内容 | 轨迹/任务/记忆/感官（审计面） | 卡片/对话/宇宙/线索（表达面） |
| 数据 | 只读为主 | scene 流 + intent 回流（已有协议） |
| 入口 | 工作台 → 身份 → tab | 舞台 = 默认落地页 |

**双面一体**：舞台上的每张卡片都能下钻进观测台对应视图（卡片 →
轨迹步/任务详情）；观测台的每个对象都能"推上舞台"（任务 → progress
卡）。两端经同一 scene 流同步，互为表里。

### 2.2 概念三句话

- **舞台是心智的居所**——打开应用 = 走进它的空间：宇宙是房间的
  氛围，卡片是它摆在桌上的事，对话是你们之间的对话；
- **心智是导演**——它按 Scene 协议声明"此刻舞台上有什么"（已有
  协议，本设计把它升为界面组织原则）；
- **人是观众与审批人**——你看它的演出，在 confront 时刻介入决策，
  平时不必翻它的抽屉。

## 3. 信息架构重构：两个一等空间

### 3.1 舞台（Stage）——默认落地页

替代现在的"身份 tab 首屏"。四层叠合（z 序从底到顶）：

| 层 | 内容 | 来源 |
|---|---|---|
| **氛围层** | 宇宙（已有 scene-cosmos：核心球/思考者星体/任务弧/预算环）——从"装饰"升格为**状态真实投影**：星体亮度=思考者活跃度、轨道弧=在途任务、外环=预算水位（数据已有） | scene-cosmos 保留，数据源不变 |
| **场景层** | Scene 卡片（text/progress/choice/metric…）：心智的表达与提问，intent 驱动呈现 | /scene/stream（已有） |
| **对话层** | 常驻对话条：最近的你↔心智 exchanges（气泡，限 3 条）+ 底部输入。展开 = 全屏对话（现 chat 页内容迁移为舞台的展开态，不再是独立 tab） | chat 契约复用 |
| **线索层** | 开放线索/最近工作的一行式摘要（thread + worklog 的舞台投影，可点击下钻） | thread.json + 轨迹 action |

**引擎室**（现有 6 tab 的去处）：舞台右上角「引擎室」入口 → 右侧
滑出抽屉（40% 宽），内含原 tab 内容的瘦身版；深度审计（轨迹全文/
任务详情）= 全屏跳转既有路由。tab 不再是一等导航——**检修是动作，
不是地方**。

### 3.2 工作台保留（多身份总览，职责不变）

年轮 §5.1 的「需要你/心智卡网格」设计照旧；心智卡的主动作从
「进入轨迹」改为「进入舞台 →」。

### 3.3 导航模型

- 落地页 = 最后活跃身份的舞台（工作台入口在左栏顶部）；
- 舞台内导航 = 命令面板（Cmd/Ctrl+K，已有 mindlog-search 可扩展）
  + 引擎室抽屉；
- 传统路由全部保留（书签/深链兼容），从舞台可达。

## 4. Scene Protocol v2：支撑舞台的协议扩展

### 4.1 词汇表扩展（kind v2）

| kind | 用途 | 舞台呈现 |
|---|---|---|
| text/progress/choice/metric | （已有，§4 v1） | 卡片 |
| **thread** | 开放线索摘要卡（id 关联 threads.json） | 舞台左下线索星带，点击 = thread update |
| **worklog** | 最近工作一行流（只读，由注入段同源派生） | 舞台底部暗色行 |
| **focus** | 专注横幅（已有 push-bell 同款语义） | 全宽横幅 |

### 4.2 编排事务（choreography）

心智的一次行动常涉及多张卡（progress 推进 + thread 更新）。扩展
`ui set --batch <json>`：一次落**一条** scene 步骤含多个 op——投影
端单帧应用，消除多卡闪烁（协议向后兼容：单 op 形态不变）。

### 4.3 生命周期

- ambient 卡默认 TTL（1h，可 --ttl 覆盖），过期投影端自动降透明
  并移出堆叠（轨迹原文不动——过期是呈现语义）；
- confront 卡不过期（等决策），但同一时刻至多一张（已有约束）。

### 4.4 intent 回流 v2

已有 choice→policy.Decide。新增：`dismiss`（用户关卡，落轨迹作
上下文）、`expand`（请求详情，回注 manifest 标记）。都不叫醒心智。

## 5. 动效叙事（与年轮 §3.4 的关系）

年轮的 120/200/320ms 是**铬件动效**（态变/浮层/入场），保留。
新增**叙事动效**层（舞台专用，全部 reduced-motion 降级）：

| 事件 | 动效 | 时长 |
|---|---|---|
| 卡 upsert | enter：intent 驱动——ambient 淡入呼吸 / inform 上浮 / confront 遮罩+缩放聚焦 | 320ms |
| 卡同 id 更新 | morph：data 变化原地过渡（progress 平滑推进） | 200ms |
| 卡 remove | exit：confront 确认后收缩消散 | 200ms |
| 心智开始工作 | 宇宙层 working 态：轨道弧点亮、核心球呼吸加速 | 持续 |
| 任务完成 | 完成弧闭合 + 一次叶绿脉冲（不做彩带） | 600ms |

**纪律**：动效表达的是**状态迁移的事实**，不是装饰——每个动效都
能回答"什么变了"。celebration 类仍然禁止（年轮 §3.4 边界不变）。

## 6. 交互模型

- **对话**：舞台底部常驻输入条；Enter 发送（responder 请求档）；
  需要深聊点开全屏对话（展开态保留现 chat 页全部能力，含目录/
  深链）；
- **命令面板**：Cmd/Ctrl+K——跳转（轨迹/任务/记忆…）、动作
  （ui set 模板、thread add）、身份切换；键盘党的一切入口；
- **审批**：confront 卡即审批 UI（Phase 2 已通），**全局弹出——任何
  视图上都会出现**（2026-10-13 用户裁决：审批窗口必须全局；工作台
  与任务页的既有审批提示保留，三处共示同一待批队列），决策落
  policy.Decide，企微与桌面双端共存语义不变；
- **触达分级**：ambient 永不打断；inform 常规；confront 遮罩+
  声音（可选，跟随系统）。

## 7. 技术架构（前端，后端协议已就绪）

```
StageRoute（/i/:id/stage，默认落地）
├─ CosmosLayer        （scene-cosmos 保留：氛围 + 状态星图）
├─ SurfaceLayer       （scene-layer 重构：SSE 折叠 → kind 注册表渲染）
│   └─ kindRegistry   （text/progress/choice/metric/thread/worklog…）
├─ ConversationStrip  （chat 契约复用：最近 3 条 + 输入 + 展开态）
├─ ThreadStrip        （thread.json 摘要行）
└─ EngineRoomDrawer   （6 tab 瘦身版抽屉 + 深链到全屏路由）
```

- 折叠器/判重/密度上限全部复用既有实现；新增的只有 kind 注册表与
  编排事务的投影端消费；
- 旧路由全保留（书签/深链/审计习惯），舞台是新增的默认视图。

## 8. 分期（确认后执行；每期独立验收）

| 期 | 内容 | 验收 |
|---|---|---|
| A 舞台骨架 | StageRoute 四层 + 引擎室抽屉 + 默认落地 | 打开应用落舞台；卡片/对话/线索同屏；引擎室可达 |
| B 叙事动效 | kind enter/morph/exit + intent 强度 + working 态 | 推卡看动画；reduced-motion 降级；宇宙 working 呼吸 |
| C 编排事务 | ui set --batch + 投影端单帧应用 | 多卡操作无闪烁 |
| D intent v2 | dismiss/expand + 通用 choice 回流落轨迹 | 非审批卡也可交互且可审计 |

## 9. 待确认决策点（实施前需拍板）

1. **落地页**：舞台取代工作台成为默认落地（工作台一跳可达）——
   还是保留工作台落地、舞台为身份默认页？本文倾向前者。
2. **对话层形态**：常驻条 + 展开态（本文方案）vs 保留独立对话 tab
   双入口并存？
3. **引擎室形态**：右侧抽屉（本文方案）vs 保留顶部 tab 行？
4. **宇宙层的地位**：升格为状态投影（本文方案，需要把 thinkers/
   budget 采样接实）vs 保持纯氛围？
5. **视觉基调**：宇宙绿（现有）延续，还是借机引入剧场灯光语汇
   （暖光/追光）？本文倾向延续年轮绿、只加 intent 驱动的色调浓度。

## 10. 明确不做

- 不做多身份同屏舞台（工作台已承担总览）；
- 不做语音/动画角色扮演层（pet 页已承担表达彩蛋）；
- 不做 agent 自由布局（core 永远只有 scene 声明，无像素控制
  ——BaiLongma 红线照抄）；
- 不删任何审计路由（合规与排查习惯优先）。
