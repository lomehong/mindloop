# 设计：感知系统（五感：眼·耳·鼻·舌·身）

状态：v1.1（2026-10-02 立项；同日用户质询"是不是应该是五感"后
修订——v1 把手混进感官清单是分类错误：手是效应器不是感官。改用
六根框架：眼耳鼻舌身是五根，第六根"意"即思考者本身，mindloop
已经拥有——本设计不是给 agent 装脑，是给已有的脑装身体）。
依赖：`connectors.md`（传输与投递语义）、`proactive-reporting.md`
（触发源矩阵、内容分级 L1-L4、quiet 窗口、降噪纪律）、
`roadmap.md` §0.3（依赖分层——感官属协议适配层，可引库）、
roadmap §2.4（记忆代谢——provenance 章与未核实降权，感知事件的
注入面防御直接复用）、robotgo 方案存档（手：独立 robotd MCP
server、cgo 不进主二进制）
关联：`internal/connector`、`internal/schedule`（KindPatrol——眼
的雏形）、`internal/mind/dispatcher.go`（WakeKind 词表）、
`internal/mem`（记忆循环）、`internal/obs`（分级预算/空转率）、
`internal/policy`（风险门/tripwire/undo——手的安全链）

## 1. 愿景：从反应式到有机体

一句话：把 mindloop 从"唤醒驱动的反应式 agent"（输入只有用户的
话和时钟）升级为"感知驱动的有机体"（世界本身成为输入流），并以
手闭环——感知 → 决策 → 出手 → 感知出手的结果。

"眼睛里有事"的三层工程含义（立项讨论已确认）：

1. **感知带议程**：感官输出的不是原始数据，是"与自己事务相关的
   事件"——透过手头的任务、承诺、记忆去看。这是"眼里有活"与
   "监控探头"的分界。
2. **看见 ≠ 打扰**：大部分被看见的事安静沉淀为记忆，只有足够
   重要的才升级为唤醒、提案或行动。分级预算（obs）从"预算管理"
   升级为"注意力管理"。
3. **感知落到动作**：手让"告诉你 CI 红了"升级为"去查、去修、
   去验证"。主动性 ≠ 自治不变：手的每个动作过既有风险门
   （policy）、不可逆守卫（tripwire）与撤销（undo）。

**判感官真伪的标准（v1.1 补）**：五感的意义在机制账，不在比喻的
完整性——每多一感必须挣到一个独立机制，否则就是叙事膨胀。舌挣到
的是"摄入品评"（味觉信号 + 校准回路 + critic 的数据面），身挣到
的是"动作必须自带验证感知"（触觉回路）。它们过了这道检验。

## 2. 目标与非目标

**目标**：

- 统一的感知事件模型与显著性分级（S0-S3）——四感共用一套神经
  系统，不为每个感官各造一套调度；
- 事件落轨迹（日志即 API、视图皆派生、可审计），唤醒有归因档
  （`WakeKind=sensor`），预算有账（自发档）；
- 分期交付：眼（状态观察）→ 耳（消息流泛化）→ 鼻（异常嗅探）
  → 舌（摄入品评）→ 身（触觉与动作闭环）。分期顺序不是难度排序，
  是**承诺梯度**：从远感（读为主）到近感（摄入/出手），越近承诺
  越重、门越重（§8）。

**非目标**：

- 不做实时流处理系统——事件判定是轮询/回调上的纯函数加便宜
  统计，不上消息队列、不引流式框架；
- 不做无门槛自治——S2 以上唤醒走自发档预算，手走审批门，
  "主动性 ≠ 自治"是戒律不是开关；
- 本设计不含字面模态（屏幕视觉、语音）——隐喻通道（文件/网页/
  消息/事件流）先行，字面模态待感知闭环验证后另行立项（§9.3）；
- 不做感知规则的市场/共享形态——先服务单身份。

## 3. 现状盘点：四感的雏形已在

| 感官 | 已有雏形 | 缺口 |
|---|---|---|
| 眼（状态观察） | `KindPatrol`（every+task 周期巡检）；alert（exec 失败叫醒） | 巡检靠模型轮询太贵、粒度粗；文件/网页/仓库的世界状态无常驻低耗观察者 |
| 耳（消息流） | 企微 bridge 入站（白名单 fail-closed、幂等键、rewound 防护） | 入站是"消息"的特例路径，未抽象为感知事件；webhook/邮件等通道无位 |
| 鼻（异常嗅探） | llm-health 健康周报（事后）；stats 空转率 | 没有对事件流的模式偏移检测（速率突增/首次出现/缺席） |
| 舌（摄入品评） | 审批通过/拒绝、建议被忽略、undo、任务返工——味觉信号已全落轨迹 | 信号无人品尝：未一等化、S 阈值无地面真值、critic（roadmap §3）无数据 |
| 身（触觉与行为） | 沙箱 exec + 连接器出站（发消息）+ 审批门/undo | 世界级动作无位；动作无验证感知（麻醉式自动化）；robotd 方案已存档未立项 |
| 神经系统 | WantWake、watchdog、coalesced 槽、quiet 窗口、分级预算 | 缺统一的事件→显著性→唤醒门；各感官的降噪要重造 |

结论：**缺的不是机制，是"感知事件"这个一等公民**——把五感的
输出统一成一种落轨迹、可分级、过注意力门的东西，神经系统就全通。

## 4. 总架构：两层神经系统 + 感知事件

### 4.1 感知事件（新步骤类型 event）

感官的输出是轨迹上的 event 步骤（新类型词表，与 alert 同级）：

```
traj.NewStep(traj.TypeEvent)   // "event"
Fields: source=<sensor-id>      // 感官通道（file:.../web:.../git:.../wecom:.../hook:...）
        kind=<changed|appeared|removed|spike|threshold|anomaly>
        subject=<归一化主体>     // 路径/URL/仓库/会话
        salience=<s0|s1|s2|s3>  // 反射层判定（§4.3）
        dedup=<内容指纹>        // 同主体同类事件的去重键
        digest=<人话摘要 ≤200 字> // 反射层能给的上下文（diff 摘要/标题）
```

为什么落轨迹而不是内存总线：日志即 API 是第一戒律——事件可审计、
可重放、视图皆派生（stats 从 event 步骤派生信噪比）；Windows 上
跨进程事件总线是新 IPC 面，而轨迹追加是已验证的多写者热路径
（bridge 入站在用）。event 不进人类消息 FIFO（同 alert 的理由，
proactive-reporting §3.2）：S2 唤醒走合成唤醒路径，S0/S1 只沉淀。
事件源也不止外部世界：operator 的反馈（批准/忽略/撤销——味觉）与
自身健康预算（内感受）同样走 event 管线（Phase 3/4），同一套
神经系统指向内外。

### 4.2 感官 = 新一类连接器（sensor 子包）

`internal/connector/sensor/` 新增感官家族，窄接口（装配层闭包
持有轨迹写位，sensor 包不 import traj——与 schedule.Options.Alert
同构，包保持纯逻辑）：

```go
// Sensor 是一个感知通道。onEvent 由装配层提供（构造 event 步骤
// 落盘）；实现只负责观察与反射判定。
type Sensor interface {
    ID() string
    Watch(ctx context.Context, onEvent func(PEvent)) error
}
// PEvent 纯数据：Kind/Subject/Dedup/Digest/Salience
```

依赖政策（roadmap §0.3 协议适配层）：fsnotify（文件）、feed 解析、
git 命令包装按需引入，不手写协议。

### 4.3 反射层：显著性判定是纯函数

反射层 = 每感官的廉价判定器（常驻、零模型成本），输出 S0-S3：

| 级别 | 含义 | 处置 |
|---|---|---|
| S0 | 背景变化 | 只落轨迹，不叫醒（喂记忆代谢，§7） |
| S1 | 值得知道 | 落轨迹 + 并入下次报告/巡检的素材投影 |
| S2 | 值得现在看 | 落轨迹 + 合成唤醒（`WakeKind=sensor`，自发档预算） |
| S3 | 必须现在处理 | 落轨迹 + alert 步骤（复用 proactive-reporting §3.2 的叫醒与 coalesced 背压） |

判定是每通道配置的纯函数（阈值/去抖窗口/冷却时间/首次出现/
关键词匹配），判定依据含主体与记忆/任务的关联（§7——"事"的
来源）。S2/S3 另有两道全局闸门：quiet 窗口（顺延，语义同
effectiveFires）与自发档预算（obs 守卫在准入层拒绝）。

**预算是事件风暴的最后闸门**——感官故障最常见的形态是重复刷屏
（同一事件反复触发），dedup 键 + 冷却时间是第一道，自发档预算
兜底；再加感官级熔断（单 sensor 单位时间事件数超限自动降档 S0
并记 alert，§8）。

### 4.4 唤醒归因与预算

- `WakeKind` 新增 `WakeSensor`（"sensor"，dispatcher.go 词表）：
  与 watchdog/scheduled 同为合成唤醒族——syntheticStep 机制直接
  复用（内存构造不落盘，事件本体已在轨迹上），订阅面沿用
  monolithWakeType 常量；
- `obs` 的 isSpontaneous 扩展：`Attrib.Wake==sensor` 归自发档——
  `MINDLOOP_SPONTANEOUS_TOKENS` 对感官唤醒生效，"对话/任务保到
  最后"的分档语义不变，感官是最先被停的一档；
- stats 空转率口径扩展：sensor 唤醒中产出有意义输出的比例成为
  **感官信噪比**——反射层阈值的校准依据（§6）。

## 5. 分期

### Phase 1 眼：世界状态的常驻观察（file + web + git）

- `sensor/fs`：目录观察（fsnotify，轮询 fallback），S 判定含
  "路径是否与当前事务相关"（任务工作目录/记忆提及路径 → 升档）；
- `sensor/web`：URL/RRS 轮询（间隔下限 5m，条件请求），diff 提取
  进 digest；SSRF 约束复用 fetch 白名单形态（私网地址拒连）；
- `sensor/git`：仓库 refs/工作区观察（git 命令包装，不引 cgo）；
- 配置：身份配置新增 sensors 段（与 schedule 条目同风格），热
  加载同 bridge 配置。

验收：配一个文件感官 + 一个网页感官——S2 变化数秒内唤醒且得到
一句人话摘要；S0 只落轨迹不叫醒；同一事件改三次只醒一次（dedup）；
自发档预算耗尽时 S2 被准入拒绝且 stats 可见；quiet 窗口内 S2 顺延。

### Phase 2 耳：入站流泛化

- bridge 入站消息抽象为感知事件源（消息 = 耳朵听到的话）：幂等/
  白名单语义不变，增加 S 判定位——白名单内默认 S2（既有行为），
  可配置降档（如群通知只沉淀 S0）；
- `sensor/webhook`：service HTTP 端点新增 `/hook/<sensor-id>`，
  鉴权用既有 token 形态——任意外部系统的 webhook 变成耳朵；
- roadmap §2.3 渠道扩展（钉钉/飞书）落地后自动成为耳，零新概念。

验收：外部系统 webhook 推一条 JSON，按配置分档沉淀或唤醒；企微
入站行为与升级前完全一致（回归）。

### Phase 3 鼻：模式偏移与睡眠整理

- 对 event 流的便宜统计：速率突增（同 kind 超基线 N 倍）、首次
  出现（新 subject）、阈值越界（数值型 digest 规则匹配）、**缺席
  检测**（心跳类感官该来的没来也是事件——"没有消息"本身被感知）；
- 与记忆代谢（roadmap §2.4）合流：S0 积压由空唤醒/"睡眠整理"
  巡检消化——mem.AddWith 沉淀（analyzeNew 冲突分析直接复用）、
  provenance 章 + 未核实标签；
- 鼻的输出也是 event（kind=anomaly），可再分级——嗅到的不一定
  叫醒，但一定留痕；
- **内感受（同一机制指向内）**：`sensor/self` 监听自身健康/预算
  消耗/队列深度（llm-health 与 obs 已有数据），痛觉即既有 S3/
  alert 语义——现代感官科学补的五感之外诸觉（内感受/本体感/
  痛觉），全部复用同一套事件管线，零新机制，只是感官源指向自己。

验收：人为制造日志增速突增 → 鼻子产生 S2 anomaly；连续三天无
日报 → 鼻子报缺席；自发档预算耗至阈值 → sensor/self 产生内感
事件（先自省后停，不是突然哑掉）。

### Phase 4 舌：摄入品评与味觉信号

舌是"尝"的感官：对摄入物的质量与偏好判断——读的内容、接的
任务、自己的产出，尝过才有资格说好坏。它不是新探测器，是新
**解释器**：味道数据系统早就在排——审批通过/拒绝、建议被忽略、
undo 撤销、任务返工、显式反馈，全是轨迹上已有的味觉信号，只是
无人品尝。

- **味觉信号一等化**：operator 反馈类步骤（approve/deny/undo/
  ignore/显式评价）加 taste 解读投影，成为与 event 同级的可
  消费数据；
- **校准回路**：味觉信号是 S 分级的地面真值——"这个感知触发
  的动作被 undo 了" = 阈值过紧（不该出手的出手了）；"S0 沉淀
  的事后来被追问" = 阈值过松（该报的没报）。§6 校准从纯人工
  升级为有据可依（调参动作仍走人工评审，不做无监督自改）；
- **先尝后咽**：审批卡本来就是味觉协议——提案先给用户尝，认可
  才咽。这给"human confirm"一个感官层面的解释：近感（摄入/
  出手）必经品尝，远感不必；
- 认知层的舌 = critic 第三思考者（roadmap §3 远期不变）：低频
  复盘最近轨迹的味道（哪步错/哪浪费/什么该沉淀）。Phase 4 为
  它备齐数据，届时只写消费者、不铺新管线。

验收：undo 一次感官触发的动作 → taste 信号落轨迹且 stats 可见；
同一感知规则的累计负味觉达到阈值 → 校准报告建议降档（人工确认
后生效）；critic 启动时能直接读味觉投影（数据面就绪）。

### Phase 5 身：触觉与行为闭环（robotd）

v1 的"手"升级为"身"：触觉本就是感知-动作融合的感官，行为是
它的另一半——手没有从清单里删掉，是回到了它真正的感知身份。
工程含义是一条硬规矩：**动作必须自带验证感知，禁止麻醉式
自动化**——盲点击、无回读的盲写是 RPA 事故的经典形态。

- 按存档方案启动 robotd：独立 MCP server（cgo 不进主二进制）；
  前置：llm 客户端补图片消息（触觉的回读通道）；
- **触觉回路**：每个动作后强制回读验证（点击后截屏比对、写入后
  重读校验），act → feel → adjust 循环；验证失败走触觉异常路径
  （重试/上报/急停），不默认成功；
- 安全链全开：风险门（桌面动作不进只读白名单）→ tripwire 扩展
  GUI 自动化模式 → undo 快照（工作目录内可撤）+ 审批前置（沙箱
  外动作的补偿）→ 轨迹全程留痕；
- 手感沉淀：同一界面操作的稳定选择器/时序经验落 skills，触觉
  经验可复用。

验收："看这张截图，把里面的数值录进 X"类任务全链走通——理解、
操作、回读验证、汇报，每步有审批卡与轨迹；人为制造验证失败
（点错窗口），心智走触觉异常路径而非假报成功。

## 6. 注意力管理与校准

- 预算控制台（stats/doctor）增加感官维度：各 sensor 事件量、
  S 分布、唤醒次数、信噪比；
- 反射层阈值用保守缺省（宁 S0 勿 S2），校准依据 = 信噪比数据 +
  **味觉信号**（Phase 4 起为地面真值：undo/忽略/显式反馈）+
  用户一句话反馈（"这个别再报了"→ 降档规则）；调参动作仍走
  人工评审，不做无监督自改——味觉提供证据，不提供自动权。
- 通知分级对齐 proactive-reporting L1-L4：S1→L2 报告素材、
  S2→L3 报告/摘要、S3→L4 告警路由。

## 7. 记忆循环："事"从哪来

"眼睛里有事"的"事"= 记忆与任务定义的相关性：

- 观察配置引用记忆/任务（watch 路径 = 当前任务工作目录、watch
  关键词 = 记忆中在意的项目名）——感官不是裸配置，是议程的投影；
- 感知喂养记忆：S0/S1 沉淀进 mem（未核实标签 + provenance），
  睡眠整理负责合并/裁决/降权——感知喂记忆，记忆反过来定义什么
  是"事"，经验循环闭合；
- 外部内容衍生的记忆注入 prompt 时降权（roadmap §2.4 防投毒）——
  感官是 prompt injection 的最大攻击面，此条是安全项不是优化项。

## 8. 安全边界汇总

- **门集中在接触面（远近感原则）**：远感（眼/耳）读为主，风险与
  成本都低；近感必然承诺——舌要摄入（投毒/注入面），身要出手
  （副作用面）。防线因此有感官依据：注入防御挂在舌（§7），审批/
  undo 挂在身，不在远感上浪费摩擦；
- **不可信输入**：一切外部感知内容（文件/web/消息）按不可信
  处理——digest 进 prompt 带未核实标记与降权；web 感官 SSRF
  约束（私网拒连）；
- **事件风暴**（四道闸）：dedup + 冷却（反射层）→ quiet 顺延 →
  自发档预算准入拒绝（obs 守卫）→ 感官级熔断（超限降档 S0 +
  alert）；
- **身**：审批门不豁免；tripwire 扩展 GUI 自动化；触觉回读强制
  （动作自带验证，失败不默认成功）；沙箱外动作以审批前置补偿；
- **隐私**：感官配置与事件全在本地身份目录，外发仍走显式 `to`
  路由（路由即数据，无隐式外发）。

## 9. 开放问题

1. S 判定的"与事务相关性"第一版做多细——建议只做路径/关键词
   集合匹配（便宜、可解释），语义相关性留给记忆代谢的检索升级；
2. fsnotify 在高频目录（node_modules 类）有事件洪泛前科——
   轮询 fallback 的切换阈值与排除规则需 Phase 1 实测定；
3. 字面模态（屏幕视觉/语音）启动时机——建议感知闭环（Phase 1-3）
   跑出信噪比数据后再立项，届时 llm 图片消息已随 Phase 5 落地；
4. sensor 配置的 UX 形态（init 向导预设 / 仪表盘管理页）——
   Phase 1 先配置文件，仪表盘页等真实使用反馈；
5. critic（舌的认知层）与 Phase 4 味觉数据面的启动间隔——建议
   Phase 4 落地后先积累一轮真实味觉数据，critic 立项时以数据
   质量为准入条件。
